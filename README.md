# UserEcho

面向香氛用户反馈的洞察工具：将 CSV 中的反馈整理为主题统计、问题优先级、风险警报与人工复核清单。需求定义见 [PRD](docs/PRD.md)，当前实现范围与验证结果如下。

## 核心流程与技术栈

上传 CSV → 数据检查 → LLM 多标签分类 → 确定性校验 → 优先级与风险分析。

使用 Python 3.11+、Streamlit、pandas、Pydantic、OpenAI 兼容 API 和 pytest。分类候选携带来源片段与提及类型，经过原文子串校验、去重、过滤后最多保留三个主题；不可靠的候选按规则进入人工复核。优先级与风险标志由代码计算，Impact 是负责人设定的业务规则。

## 方法与限制

真实数据按 respondent_id 划分开发集与评测集，避免同一受访者跨集合。参考标签由 AI 辅助生成并审核，项目负责人完成边界裁决；标签形成过程受到 AI 辅助及校准讨论影响。历史裁决存在个别严重度差异，详见 [决策日志](docs/decision_log.md)。

执行前校验冻结 CSV 的 SHA-256；按 feedback_id 对齐，在固定主题集合上累计 TP、FP、FN，忽略主题顺序。人工复核及未处理项按空预测纳入统计。本轮只评估主题识别，不将该 F1 解读为整条反馈的分类正确率，也不计算情绪、严重度或复购的 F1。

High-risk Recall 按单条反馈计算。参考标签中没有高风险正样本，因此分母为 0；系统识别出的 1 条风险不能用于证明风险召回能力。source_span 的原文子串校验不等于报告结论的 Evidence Support Rate。人工处理时间未记录，未进行人工与系统耗时对照。

候选主题和 mention_type 仍由 LLM 产生；确定性后处理降低但不能消除批次上下文影响。原文片段存在不保证语义归因正确，temperature=0 不保证结果正确。评测完成后不再根据本次差异调整 Prompt；Bad Case 仅记录系统限制和后续优化方向。结论级证据、建议生成等未完成部分不作为已交付能力。

**n=13，仅用于小样本工作流可行性及参考标签一致性检查，不代表生产环境表现。**

## 隐私措施

原始问卷、真实开发集 CSV、真实评测及标签 CSV 均由 .gitignore 排除；公开文档只记录汇总指标及不含原文的主题差异。API 凭据保存在本地 .env，不提交。默认日志不输出反馈或来源片段；`USERECHO_DEBUG_PROMPT=1` 会启用完整 Prompt 日志，处理真实数据时保持关闭。分类会将待处理文本发送到配置的模型服务，请仅上传获授权且已匿名化的反馈。

评测原文仅由评测程序读取；结果报告不保存反馈原文、来源片段、API key 或完整 Prompt。评测目录的方法说明已同步到本 README 和决策日志，无需为展示方法提交真实数据或目录说明文件。

## 本地运行

在项目根目录执行：

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

在本地 .env 中设置 `LLM_API_KEY`、`LLM_BASE_URL` 和 `LLM_MODEL`，然后运行：

```bash
streamlit run app.py
```

离线测试：

```bash
pytest -q
```

API 相关测试使用 Mock，不调用外部服务。上传 CSV 至少包含 `feedback_id`、`feedback_text`；少于 5 条仅展示概览，清洗后超过 200 条会提示截断，只处理前 200 条。
