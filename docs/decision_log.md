## 2026-09-26 提交前审查：拒绝粒度与重试口径

### source_span 失败采用“按反馈整体拒绝”

任一候选的 source_span 去除首尾空白后为空或无法在对应原文中精确找到时，整个反馈的所有候选主题一起退出自动分类，反馈进入 review_items，reason=source_span_not_in_feedback；不只删除证据失败的那个主题，也不保留同条其余候选作为成功分类。该条不触发 LLM 重试，其他反馈独立处理。

这是“按反馈整体拒绝”的粒度选择，遵循负责人批准的顺序：先校验全部候选证据，再去重、过滤和裁剪。原因是单条证据不可靠时，继续发布部分标签可能隐藏缺失的主题或风险，并改变本条的主题选择；将整条交人工复核能保持结果归属明确，避免一条反馈同时被计为成功和待复核。代价是同条有效候选也暂不发布，复核量可能增加。当前 review_items 只保存 feedback_id 与原因码，并不内嵌所有候选的副本；“所有候选一起进入复核”指处理粒度，而非已实现候选快照存储。

### 已成功反馈在批次重试中重复发送：现状及建议

当前 active_batch 只排除 terminal，不排除 successes，因此同批其他条目需要重试时，已成功分类的反馈会再次发送给 LLM。successes.setdefault 保留首次成功结果，不被后来输出覆盖；已进入语义复核的 terminal 条目不会重发。

该行为沿用此前已允许的整批重试策略，不能把它追溯描述为已经验证有效的“批次结构稳定性优化”。重发成功条目确实能保留部分上下文，但 terminal 被移除时批次仍然改变，也没有对照证据证明这种做法提高稳定性；其代价是重复 token 与处理时间。

建议后续经负责人确认后改为仅发送尚待处理的反馈，同时固定首次成功结果、继续排除 terminal。这样可减少重复调用内容，使处理边界更清晰；但缩小批次也会改变模型上下文，应先做受控开发集对照，核对残余失败条目的结果及成本。本轮仅记录建议，不修改代码，也不将建议写为已经批准的产品决策。

### HTTP 状态码的可重试边界

当前实现对 APIStatusError 的 HTTP 408、409、429、500–599 允许进入现有重试预算，其余 HTTP 状态转人工复核、不自动重试。网络连接/超时错误，以及 JSON 解析、Pydantic 校验、返回结构缺失或损坏仍按各自既有规则处理；source_span 失败与全 uncertain 属语义复核，不适用 HTTP 重试。

依据：408 表示请求超时，409 可能是可暂时恢复的冲突，429 表示请求限流，5xx 表示服务端错误；这些状态具有重试恢复的可能。该集合也与项目当前安装的 OpenAI 兼容 SDK 默认重试状态集合一致。此处是有上限的恢复策略，不保证所有 409、429 或 5xx 都能通过重试解决。其他状态（例如 400、401、402、403）通常需要调整请求、凭据、余额或权限，重复相同请求通常不能解决，因此停止自动重试并交人工处理。

SDK 客户端 max_retries=0，重试由分类模块统一计数，每批最多三次尝试、整次任务最多 15 次调用，避免 SDK 隐式重试绕过预算；本轮不新增等待、退避或 Retry-After 行为。
